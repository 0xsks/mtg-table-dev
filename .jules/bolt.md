## 2024-05-24 - Extracting heavy string operations from huge hot loops
**Learning:** In projects like `mtg-table` where large in-memory collections (36k+ cards) are searched using JS array methods without external databases or caches, putting regex string replacement (`qLower.replace(...)`) and string splitting/matching operations (`cmcParam.split(",").some(...)`) inside the iterative `.some()` or `.filter()` logic drastically impacts performance.
**Action:** When filtering in-memory arrays larger than 10k items, strictly trace string allocations, regex processing, parsing, and type conversions to happen *once* outside the primary loop execution context. Use pre-parsed variables (like `parsedCmc`, `sortedColorsStr`) for fast `===` value comparisons or simple boolean property checks per iteration.
