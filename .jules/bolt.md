
## 2026-10-16 - Hot loop optimization for in-memory card search
**Learning:** In a codebase that relies heavily on large in-memory array filtering (e.g., looping over 36,000+ objects), operations that allocate new memory (like string slicing, regex parsing, and array spreading `[...arr]`) inside the loop are extremely expensive. While replacing functional array methods (`.some()`, `.every()`) with standard `for` loops provides some speedup, the most significant performance gains come from computing and caching strings/arrays exactly once during startup (or outside the query loop), and using those pre-computed values during the iteration.
**Action:** When working on the `searchCards` function or similar in-memory loops, always look for string manipulations, spread operators, or repeated conversions. Move them out of the loop by pre-computing values on the objects during initialization, and structure the search loop to compare against these cached primitives directly.
