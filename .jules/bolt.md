## 2024-11-20 - Fast in-memory array search optimizations
**Learning:** In a heavily used in-memory search loop like `searchCards`, parsing queries (e.g. `toLowerCase()` or string replacements on search parameters) and doing complex setups (like sorting color string queries) inside the `for` loop iteration over 36k items adds massive overhead. Also, `localeCompare` is notoriously slow in V8; basic relational operators (`<`, `>`, `===`) are significantly faster for sorting string fields like `c.name`. Furthermore, ensure query constraints (like empty `cmc` parameters rendering into empty arrays) are adequately filtered so they don't block out the rest of the search check if incorrectly assumed truthy when empty.
**Action:** When filtering in-memory over tens of thousands of items, pre-parse string transformations and query constraints *outside* the loop, cache card text transformations into normal fields upon initial server load, replace `localeCompare` with `a < b ? -1 : 1`, and safely handle edge-case constraint properties like `undefined` or `[]` before and during iterations.
