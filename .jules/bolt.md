## 2025-02-18 - Optimize in-memory array searching logic (searchCards)
**Learning:** In large (30k+ records) array iterations, string manipulations (`.replace`, `.toLowerCase`) inside the loop, regex evaluations on array-converted string primitives (`[...str]`), and `localeCompare` for sorting significantly slow down the loop execution. Pre-computing constraints (like CMC parts, parsed query terms) outside the loop and replacing array spread operations for basic strings iterations, along with direct boolean sort checks (`a < b ? -1 : 1`) improves the loop performance substantially.
**Action:** When filtering massive in-memory arrays (like card catalogs), perform constraint setup and string normalization outside of the evaluation loop. Avoid generating implicit arrays out of strings using spreads if basic string character index access (`str[i]` or `.includes()`) can suffice, and prefer `a < b ? -1 : 1` string comparisons to `localeCompare` in sort predicates.
