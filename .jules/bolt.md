## 2024-10-21 - [Precompute Search Indexes and Sort Without localeCompare]
**Learning:** In Node.js applications with large in-memory arrays (like iterating over 36k items repeatedly in a search query), evaluating regex replacements (e.g., \`replace(/[\\x27\\x60\\u2019]/g, "")\`) and case conversions (\`toLowerCase()\`) inside the search loop causes significant overhead. Additionally, \`localeCompare\` is much slower than simple comparison operators (\`a < b ? -1 : 1\`) for string sorting.
**Action:** Pre-compute canonical string representations (e.g., \`_nameLower\`, \`_nameClean\`, \`_typeLower\`) at initialization rather than inside hot \`for\` loops. Replace \`localeCompare\` with standard boolean string comparisons. Pre-parse search constraints (like CMC parts) outside the loop whenever possible.
