## 2024-10-31 - Hoisting string allocations/regex/array pre-parsing from `searchCards` loop

**Learning:** In a highly iterated hot loop on large JSON payloads representing a database (like iterating ~36k items for `searchCards`), small overhead from continuous allocations (`[...colors]`), mapping constraints (`cmcParts.map/some(Number)` or `p.endsWith('+')`), executing regex patterns like `replace`, or using built-in high overhead sorting like `localeCompare` create massive performance regressions. Memory allocation and heavy runtime lookups inside these large iteration loops should be avoided.

**Action:** Pre-calculate frequently accessed text fields (`name` to lower/clean format, `type_line` to lower format) onto the objects before initialization or cache them. Furthermore, pre-parse constraints before filtering the pool. If a query provides strings, turn them into integers and booleans ahead of loop execution. Replace heavy standard string functions like `.localeCompare` with raw boolean comparison operators inside sorting functions. Always verify array filters pre-allocate correct truthiness (like parsing empty values correctly) to ensure functional logic isn't broken.
