## 2026-10-13 - [Precomputing loop variants in card search]
**Learning:** Moving `.toLowerCase()`, regex string replacement, array sorting, and complex parsing out of the `searchCards` loop is essential. The V8 engine has a hard time optimizing loops dynamically doing string manipulations and regex generation 36k+ times on a hot path, causing memory overhead. Modifying `.some()` and `.every()` inside the loop back to explicit `for` loop did not drastically improve performance for very small arrays and is not worth degrading readability, as well as breaking exact matching by shadowing variables in closures accidentally.
**Action:** When optimizing loop invariants in JS engines, hoist string matching preprocessing outside the loop first and do not manually inline higher order array methods if the array is short, to keep readability. Always be careful to not shadow array elements or variables when converting higher order array methods to explicit `for` loops.
